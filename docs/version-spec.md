# Balanced Version 0.1.0 草案

双平衡三进制软件版本规范。本文定义地址、变更方向、发布身份与比较规则；适用于愿意显式保存渠道及兼容性元数据的项目。它是一项实验性提案，尚不是包管理器通用标准，也不与 SemVer 的版本字符串兼容。

“必须 / MUST”是符合规范的必要条件；“禁止 / MUST NOT”是禁止事项；“应该 / SHOULD”允许有记录的合理例外；“可以 / MAY”是可选行为。

## 1. 公共接口与发布身份

1.1 项目必须定义公共接口，包括 API、配置、数据格式及对外行为。项目必须声明版本使用的发布线 line，以及适用的尺度策略。

1.2 发布身份必须为 (project, line, sequence)。sequence 是该发布线内唯一、严格递增的非负十进制整数，必须用规范十进制字符串保存（0 或非零数字开头，禁止前导零）；比较实现必须使用精确整数。不同发布线的序号禁止直接比较。

1.3 每条已发布记录必须保存 address、channel、action、precision、compatibility 和不可变的制品标识 artifact。发布后禁止覆盖相同身份下的内容。构建时间或 Git SHA 禁止被当作顺序数值。

1.4 DBT 地址可以重复。渠道、不同分支以及撤销后重发可以占据同一地址；禁止只用地址唯一标识发布。制品元数据不参与地址比较。

## 2. 地址语法与规范化

2.1 对外规范地址必须带 & 前缀，整数部分至少一位。数字只能使用 1–9；5 是零。小数点只能出现一次，且其后必须有数字。禁止负号、指数、空白、0、alpha 后缀或 build 后缀。

```text
address  = "&" integer [ "." fraction ]
integer  = digit { digit }
fraction = digit { digit }
digit    = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9"
```

2.2 规范地址必须移除冗余整数前导 5 与小数末尾 5，保留至少一位整数；空小数部分连同小数点删除。全零地址必须为 &5。例如 &55514.855 规范化为 &14.8。

2.3 交互输入可以容忍省略 & 和首尾空白，但输出必须使用规范地址。这是输入便利，不扩展对外地址语法。

2.4 本草案的互操作范围限制为规范地址最多 48 位整数、12 位小数。实现必须在超出范围时报告错误，禁止截断。页面生成器额外只开放 p=0–3，这不是数学精度的限制。

## 3. 九宫格与算术

3.1 每个数字表示两个平衡三进制位 (B,F)，按下列九宫格排列；每个格子继续按同样顺序细分九格。

```text
6=(-1,+1)   1=(0,+1)   8=(+1,+1)
7=(-1, 0)   5=(0, 0)   3=(+1, 0)
2=(-1,-1)   9=(0,-1)   4=(+1,-1)
```

3.2 B 和 F 的数值必须分别为各位分量乘以 3 的位权后的和。整数个位权重为 1，小数第一位为 1/3；它是基数为 3 的二维系统。禁止用十进制 parseFloat、九进制或无进位运算替代。

3.3 高位确定大区域，低位在该区域中选小区域；每层边长缩小为 1/3。&14.8 的路径是 1 → 4 → .8，权重分别为 3、1、1/3，得到 (B,F)=(4/3,7/3)。有限地址表示最终区域的中心点；尾随 5 留在中心。

3.4 加法必须对两轴分别进位，余数保留为 -1、0、1，再映射为数字。示例：&1 + &1 = &19；&7 + &3 = &5。地址中出现 7 或 9 可能只是进位结果，禁止从单个字符推断发布行为。

## 4. 变更方向与尺度

4.1 定义 u=3^-p，precision=p；p 必须为 0–12 的整数。常规稳定功能事件 feature 必须令 V′=V+(0,u)，沿 1 方向；常规独立修复事件 fix 必须令 V′=V+(u,0)，沿 3 方向。

4.2 项目应该按影响范围声明尺度，例如整数用于较大迭代，小数用于更细的迭代。精度禁止等同于改动行数、功能数量、严重度评分或兼容承诺；地址中的小数位不是 SemVer 的 minor 或 patch 字段。

4.3 一个发布可以聚合多项变更。项目必须记录各项事件及其精度，并按事件增量求和；可以仅用主导事件展示摘要。禁止因展示摘要而丢失真实事件。页面演示器一次只记录一个事件。

4.4 backward-compatibility 事件沿 9，V′=V+(0,-u)，用于高版本主动适配旧接口或旧行为。通常不使用；必须声明适配对象、兼容范围、验证依据及支持期限。普通 bug 修复禁止因为服务于旧用户而自动归入 9。沿 9 不表示删除实际能力。

## 5. 不稳定功能与成熟

5.1 从稳定基线 V 引入单个不稳定功能，preview 地址必须为 P=V+(-u,0)，沿 7。记录必须保存 baseline=V、target=V+(0,u)、precision=p、channel=preview。

5.2 同一功能成熟前，项目必须完成其声明的测试和发布验证。promote 必须到达保存的 target；在基线未变时，增量为 (u,u)，即撤销 7 偏移后计入 1，可编码为 8。这是功能成熟事件，禁止统计成一次独立 fix。

5.3 后续预发布构建可以保持相同地址，并用新的 sequence 与 artifact 区分。channel 必须为 preview 或 stable，渠道名称不能从 DBT 地址推导。stable 记录必须没有待成熟 target；是否稳定与是否兼容是独立声明。

5.4 若稳定分支发生修复，项目应该合并变更、重新计算 baseline 与 target，并重新验证后发布新的预发布记录；禁止暗中修改既有记录。多个实验功能可以分支管理。页面只演示一个待成熟目标，必须先成熟再继续迭代。

## 6. 兼容性与依赖选择

6.1 每条发布记录必须声明 compatibility.kind，取 compatible、breaking 或 unknown。compatible 必须附公共接口范围及验证依据；稳定渠道本身不能作为 compatible 的依据。

6.2 破坏性变更必须启用新的 compatibility.epoch，并给出迁移说明。epoch 是项目定义的兼容分组标识，禁止拿它当地址的一部分；依赖选择默认必须排除不同 epoch 与 unknown。

6.3 自动升级必须限制 project、line、epoch 和允许的 channel，并验证兼容声明。默认只选 stable。可以在满足上述条件后选最大 sequence；禁止仅凭二维大小或列表排序判定升级安全。

6.4 本草案不定义 ^、~ 等 SemVer 范围语法。依赖可以精确锁定发布身份及制品摘要；范围请求必须显式给出筛选规则。

## 7. 大小比较：精确偏序

7.1 只比较两个地址时，必须先将精度对齐到 p=max(pA,pB)，用整数 A.axis×3^(p-pA) 与 B.axis×3^(p-pB) 比较。禁止字符排序或浮点近似。

7.2 返回四种结果：equal（两轴相等）；greater（A 两轴均不小于 B，且至少一轴更大）；less（A 两轴均不大于 B，且至少一轴更小）；incomparable（一轴更大而另一轴更小）。这只是地址关系，禁止将其解释为质量或发布先后。

```text
&19 > &1                 两轴不回退
&14.8 = &55514.855       同一规范地址
&1 与 &3 不可比较         F 更大，B 更小
&7 < &5                  地址更小，但可能是更新的预发布
```

## 8. 简易列表排序与发布先后

8.1 只需要把裸地址排成一列时，可以使用字典序数值键 (F,B)：先比较精确 F，相等再比较精确 B。返回 -1、0、1。这里比较的是分数，不是地址字符串；相同地址返回 0。该规则是人为选定的展示全序，与二维偏序一致，但会人为排列原本不可比较的地址。

8.2 示例：按 (F,B) 升序，&3 排在 &1 前，因为 F=0 小于 F=1；它们仍然不可互相支配。排序不能成为兼容或稳定性判断。

8.3 比较发布先后时，必须先确认同一 (project,line)，再按精确 sequence 比较。不同发布线返回 incomparable；相同发布身份返回 equal。地址重复时依然可以得到确定的发布顺序。

8.4 最简使用建议：地址大小用四结果偏序，版本列表用 (F,B)，实际更新选择用筛选条件加 sequence。三个操作必须在 API 和 UI 中清楚命名。


## 10. 实现与参考

页面使用 BigInt 精确算术；九宫格缩放只用于绘图，不参与比较或发布决策。极细区域在有限屏幕上不可见时，必须保留文字地址与位权。
